## Self-review and corrections

1. Two final-over cases initially retained a neutral low attempt index. Review corrected them to a global attempt index consistent with their innings legal-ball count. The validator now rejects an attempt index that precedes legal balls, and a rejection fixture covers it.
2. The lunch/innings collision initially omitted the specified 60-second over duration. The corrected reference adds 40 seconds delivery, 90 seconds wicket, 60 seconds over and one 600-second innings interval: 12:59:20 becomes 13:12:30. The schema records each duration explicitly. A coincident lunch is not added again.
3. Coverage review added no-ball and wide run-outs, an ODI no-ball and three-run parity, rather than relying only on ordinary legal-ball run-outs.
4. The run-out single on a free hit now explicitly describes an abandoned run and the striker returning to the starting end. The mandatory second-run matrix explicitly specifies crossing. This avoids inferring physical ends from total runs or wicket-end identity alone.
5. The future engine gate is explicitly unavailable. Harness-control tests using known expectations are labelled as harness checks, never evidence of scorer execution.

The first executable fixture audit passed. Subsequent review corrections also passed, and no requested verification gate remains failing. Existing environment warnings about npm http-proxy configuration and the pinned ESLint deprecation remain non-fatal. No security audit is claimed.

## Event ordering decision

Record delivery, then statistical over completion where applicable. Arbitrate the result and innings before interval or player-selection consequences. If play continues, resolve intervals/delays, then request the batter before the bowler. An over event does not itself request a new bowler. Winning extras terminate before irrelevant contact, running or dismissal. ADR 007 records the exact clock sample points.

## Limits and milestone status

This pass defines and validates the reference corpus; it does **not** implement cricket scoring, reducers, terminal arbitration, clock execution, durable persistence, NRR projections, random sampling, fictional roster generation or playable matches. The terminal/clock/persistence/NRR reference cases are not engine integration tests. The arithmetic audit checks the fixture data, not a real scorer's output.

The resolution validator covers the supported contract boundary, not every cricket law, full MatchState validity, command authority, field-position law or umpire judgement. Penalty runs are explicitly reserved and rejected by this validator until an administrative scoring contract is implemented. Rain-adjusted allocations remain unsupported. The handcrafted expectations still require independent cricket-domain review as the engine is built; no external rules certification has been obtained.

M0 now has a concrete authored fixture corpus, but the validated world pack remains outstanding. M1 cannot be marked complete until a real scorer/reducer passes comparisons. This is a completed Pass 02 foundation, not a playable V0.1 release.
