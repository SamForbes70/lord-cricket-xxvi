# ADR 016: LC_T20_EVENT_CHAIN_V1 canonical event semantics
Accepted for Pass 07B. SHA256 of existing `LC_CANONICAL_JSON_V1_SHA256` canonical JSON is the sole hash primitive. Genesis = hash([`LC_T20_EVENT_CHAIN_V1`, SHA256(canonical setup), SHA256(canonical execution manifest)]). Event sequence starts at one and is strictly contiguous. Each event records `previousHash`, `stateHash=hash(canonical match core after reducing the event)`, and `eventHash=hash([version,sequence,commandId,type,payload,previousHash,stateHash])`. The terminal manifest anchors event count, genesis, final event hash, final state hash and execution manifest hash. No hidden timestamps, UI work or renderer state enters hashes.

Pure replay reads accepted events and calls only the deterministic event reducer, **never** the random/generator service. It checks each event hash and transition-state hash, validates the ledger and validates chain/manifest anchors. Seeded resimulation executes the identical command history and compares every canonical event byte. In-memory command receipts bind command ID to exact event sequence range and final event hash; a successful retry yields the identical receipt and no more events. Unsupported model/rule/world/stage/condition/engine/chain versions are rejected before simulation. These hashes detect accidents and unsophisticated tampering, **not external authentication**; an attacker able to rewrite the entire unsigned archive could recompute them.
