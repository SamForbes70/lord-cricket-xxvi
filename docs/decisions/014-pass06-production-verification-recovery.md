# ADR 014: Pinned dependency recovery and Pass 06.0 production verification

**Status: ACCEPTED, 26 September 2026.** This decision records verification and repairs within the bounded Pass 06.0 scope. It introduces no new gameplay capability.

## Baseline, diagnosis and repair

The supplied Pass 06.0 source commit was `2ae271c3b5e304ee1fe087be2bfc37bb47fd2bb0`. Its npm lockfile SHA-256 is `44e63e6db495d897f28cda25e4338839abded362cdeaa84b6bd8a5f0ddcd17df`. Direct npm registry DNS resolution was blocked in the original build container, so earlier Pass 05.1/06.0 source evidence could not be counted as production acceptance. The pinned Linux x64 npm cache was generated in an isolated GitHub Actions branch, downloaded and verified against its SHA-256 manifest, and successfully consumed by `npm ci --offline`. No dependency version or lockfile was changed.

Fresh compilation exposed a TypeScript literal-narrowing error in the generator contact branch. It was repaired by explicitly typing the contact result as the union of the wide and non-wide contact classes; this does **not** change any draw address, random algorithm, category mask or public version. Two newly added structural JSON Schema mirrors (`GeneratedDeliverySchema`, `GeneratorTraceStageSchema`) were stale. They were regenerated from the pinned Zod compiler; the 84 inherited schema files remained byte-identical. Tests were corrected to use the actual unchanged expected-revision fixture value (`82`), the actual expanded schema count (`88`), and cached AJV `$id` compilation. Lint errors in the optional offline checker and a vacuous smoke-test mapper were repaired. The batch capability smoke test was updated to assert the **present** one-attempt generator rather than the obsolete Pass 05 status. The scoring fixture CLI now reports the Pass 07 successor rather than the already-implemented Conditional Delivery Generator; fixture expectations and scoring behaviour remain unchanged.

The earlier system Chromium browser applied centrally managed localhost restrictions. The exact Playwright 1.56 Chromium 141 and Firefox 142 binaries were obtained from a network-enabled GitHub runner and checksum-verified as a separate test-environment bundle. The root-run verification container had a HOME owned by another account. Setting `HOME=/root` for Playwright corrected the Firefox launch. No browser security or content sandbox settings were weakened. An optional `LCXXVI_CHROMIUM_EXECUTABLE` launch path permits additional system-Chromium diagnostics without replacing default pinned CI browser selection.

## Acceptance scope and protocol stability

The successful repository verifier exercises a clean pinned installation, exact 88-schema drift check, full workspace build, full TypeScript checking, lint and architecture checks, full 87-case fixture audit, scorer regression against 45 valid delivery observations / 45 ledger observations / 29 invalid resolutions, frozen 24 random + 8 state-hash vectors, 15 probability vectors, 9 generator reference fixtures / 48 independent draws, the complete Vitest suite, and production compiled app/CLI/worker smoke tests in Chromium and Firefox. All tests were rerun after final source and documentation changes; machine-readable timings, exit codes, runtime/browser versions and full logs are under `docs/verification-pass06-repair/`.

The scorer, SHA256_COUNTER_V1, LC_INTEGER_PROBABILITY_V1, model and stage pack, all frozen fixture corpora and package lockfile retain their original bytes. Regenerated schema changes affect only two newly introduced Pass 06 schema mirrors. No engine, model, random, generator or rules version identifier is changed. M0 remains partial pending the fictional world pack; M1 is complete only for supported supplied-delivery scoring; M2 is incomplete, and the application is not playable.

An offline `npm audit` run with the recovered cache returned zero *cached* advisory findings; it cannot substitute for a current online vulnerability audit, which remains a separate operational check. This limitation does not change the recorded functional verification results.
