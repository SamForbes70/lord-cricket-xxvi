# ADR 015: Additive T20 execution, immutable ownership and condition policy
Accepted for Pass 07B. Starting source Pass 07A commit `98a232dc9ef18108d55cd9b3f2b57f1a16013853`, source ZIP SHA256 `34e5ed0708672ad9fd5ac4b4a85e00afdad94457d673aaa0686cdb3e5c856301`.

The published `LC_T20_SETUP_V1` snapshot and its world/rules/model/stage hashes are not modified. `LC_T20_MATCH_V1` wraps a validated, frozen deep copy with a separately pinned execution manifest. Captain and keeper IDs remain bound to their own XI. The canonical `InningsLedger` is the only owner of counters, dismissal credits, ends and quota. Match state stores ledgers and non-scoring decisions; public summaries are derived, not independently incremented. `LC_T20_CONDITIONS_V1` adds deterministic per-attempt fatigue, per-legal-ball pitch wear and ball age, a single per-over recovery policy and innings ball-age reset without altering the legacy generator pack.

The match-wide `globalAttemptOrdinal` begins at zero and increments exactly once for **every attempted delivery in both innings**. Each innings ledger's `nextDeliveryIndex` uses this ordinal as scorer/generator address, including all wides/no-balls. The immutable setup seed never enters UI/public projections; a fixture-only autopilot reads public ledgers and known XI records, not future draws. Command revisions increase once per accepted command; failed commands do not alter state or random addresses; duplicate IDs return exact prior receipts. M2 owns only in-memory receipts, not durable saving.
