# Contract coverage and pending invariants

This document records contract evolution through Pass 07A. The table began in Pass 02 and some rows describe historical contract-only state; the pass updates below are authoritative where later implementation supersedes those rows. The current repository has 91 checked/generated schemas, an executable supplied-delivery scorer/reducer, deterministic random/state-hash services, an integer categorical probability service and a verified **one-attempt** conditional delivery generator. Complete innings/match orchestration remains unimplemented.

Call structural parsers first, then the relevant semantic validators. JSON Schemas encode structure, not all cross-object rules. Contract-valid values must not be treated as legal match actions. The test suite includes invalid values and independent AJV validation, but does not claim exhaustive cricket-domain coverage.

Pass 03 update: LC_SCORING_V1 now implements delivery scoring and innings/scorecard reduction. Four new schemas bring the total to 68. All 45 golden delivery observations and 29 rejected inputs are exercised by the real scorer. See ADRs 008/009; full-match, clock and persistence boundaries remain deferred.

Pass 04 update: three strict request schemas (RandomRequest, StateHashRequest, DeterminismRequest) bring the total to 71. All prior 68 schema files retain their bytes. SHA256_COUNTER_V1 and LC_CANONICAL_JSON_V1_SHA256 now have synchronous implementations. Version literals reject unsupported algorithms at the request boundary; domain-state legality remains separately validated. See ADR 010.

Pass 05 adds 13 strict probability/model/LUT and feature-input schemas, bringing the total to 84. The 71 Pass 04 schemas are byte-identical to the archived baseline. Python structural schema mirror is provided for restricted installations, but the canonical Zod generation and AJV gates remain required for full verification. See ADR 011.

Pass 06 update and 26 September 2026 repair: four additive generator schemas bring the total to 88. The generated output of Zod 4.1.12 replaces only two stale Pass 06 mirrors; all 84 Pass 01 through Pass 05 schemas retain identical bytes. Fresh pinned TypeScript, strict AJV, Vitest, compiled scorer, Node, Chromium and Firefox checks passed. The one-attempt generator returns a scorer-validated resolution; no playable match or orchestration is claimed. See ADR 014.

Pass 07A update, 27 September 2026: three additive schemas (`DefaultWorldManifestSchema`, `T20TeamSelectionSchema`, `T20MatchSetupRequestSchema`) bring the generated total to **91**. All prior 88 schema bytes remain unchanged. `fictional-eight-01` is the static immutable published default: 160 fictional players in eight disjoint 20-player squads and eight grounds; default-specific checks reject duplicate cross-team memberships and enforce keeper, bowler, handedness, provenance and complete-format requirements. This deliberately does **not** narrow generic WorldPack imports. Published raw/canonical hashes, generator source and version, seed and independent WORLD_GENERATION vectors are checked. `LC_T20_SETUP_V1` creates a separate deep-frozen **fixture-only** T20 setup snapshot from two validated XIs and pinned rule/model/stage packs. It is not a MatchState or playable engine. Read the current `docs/CAPABILITY_MATRIX.md` and ADRs 015/016; historical pass descriptions above are retained for provenance.
