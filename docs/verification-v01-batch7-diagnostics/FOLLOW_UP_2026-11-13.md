# V01-024 follow-up, 13 November 2026

An independent re-check of the synthetic quality sweeps and the exploitation-policy comparison at larger sample sizes, after review found two statements in [REPORT.md](REPORT.md) that the data did not support. Nothing here changes result-generating behaviour (`coefficientsChanged: false`) and nothing here is an empirical claim: the model stays `synthetic-alpha-01` / `SYNTHETIC_ALPHA`.

Reproduce with `npm run build` then `node scripts/v01-024-followup.mjs 3000 80`. Results: [follow-up-results.json](follow-up-results.json).

## 1. The failed red-ball check was sample noise

The release sweep used 600 deliveries per cell (seed `LC_V01_024_RELEASE`) and recorded `higherBowlConcedesLess: false` for `RED_BALL`: 58.00 runs per 100 balls for a high-skill bowler against 57.83 for a low-skill one. The report did not mention it. In the stored follow-up (3,000 deliveries per cell, default seeds):

| Format | High-skill bowler, runs per 100 | Low-skill bowler, runs per 100 |
| --- | --- | --- |
| T20 | 82.60 | 86.87 |
| ODI | 72.00 | 75.57 |
| RED_BALL | 51.47 | 55.40 |

All six monotonicity checks (batting, bowling, seam, turn, boundary protection) are `true` in all three formats. A further run during the review at 12,000 deliveries (not stored) gave 53.19 against 57.55 for red ball, the same direction. At 600 deliveries the same sweep gave 53.17 against 59.67 under the default seed, so the spread between seeds at that size is several runs per 100 balls, which is why a 0.17 difference proved nothing. **Recommendation:** release sweeps should use at least 3,000 deliveries per cell and report a standard error.

## 2. The tactical captain does not raise scoring

The report said tactical policies "raise death-overs aggression and trade wicket risk for higher scoring". First-innings runs per policy, in the original gate (12 matches per policy) and the stored follow-up (80 matches per policy, different seeds):

| Policy | Original (12 matches) | Follow-up (80 matches) |
| --- | --- | --- |
| Neutral baseline | 92.83 | 90.80 |
| Tactical captain | 91.17 | 92.85 |
| Always slog | 85.83 | 92.72 |
| Always defend | 74.08 | 76.67 |
| Always yorker, maximum effort | 88.67 | 88.20 |
| Always short, maximum effort | 94.83 | 93.29 |

The tactical captain is 1.7 runs below the baseline in the original and 2.1 above it in the follow-up. A difference that changes sign between runs is noise, so the claim is unsupported, and so is the report's explanation of the low-scoring baseline (about 89 to 93 runs in 20 overs). The baseline is low under every policy, so it comes from the `synthetic-alpha-01` priors, not from a missing death-overs plan. Changing it needs a new model version and belongs to the empirical track. An extra 80-match run during the review (seed prefix `LC_BIGPOL`, not stored) gave a gap of +0.6.

No one-note policy is dominant on first-innings runs. Always defend scores far less. Always slog scores about the same as the baseline but is dismissed in 65 of 80 innings in the follow-up, against 21 for the baseline, so it trades wickets for no extra runs.

## 3. Mirrored pitch scenarios give identical numbers by design

"Green seam" and "dry turn" (and "flat deck" and "low turn") match to every digit because `packages/simulation/src/generator.ts` uses `turnBp` for spin bowlers and `seamBp` for pace bowlers through one shared function. This is not a defect, but it means the sweep cannot distinguish seam from turn effects. Pitch effects are small: about 1 run per 100 balls between a high and a low seam value.

## Conclusion

The V01-024 criteria are met with the corrected conclusions above: fixed paired scenarios, an investigated low-scoring baseline (attributed to the model priors), recorded monotonicity, no dominant tactic, and no change to result-generating behaviour.
