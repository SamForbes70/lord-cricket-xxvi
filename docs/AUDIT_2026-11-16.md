# Lord Cricket XXVI: audit of main at 806ef50 and plan to finish

16 Nov 2026. Read-only audit of the repository as it stands on GitHub, covering the 12 commits pushed directly to `main` since `f7ee054` (PR #43), plus open PRs #44 and #46.

## How this audit was done

- Local container, Linux, Node 22. `npm ci`, `npx tsc -b` (exit 0) and `npm run verify:09:core` were run at `806ef50`.
- Four independent read-only reviews were run in parallel: simulation and game logic; persistence, contracts and saves; web app, UX and Windows launcher; documentation and brief coverage.
- The most serious claims from those reviews were re-checked by reading the cited lines. Each finding below says whether it was **verified** (code read, or a command run) or is **[Inference]** (reasoned from code, not executed).
- Not run: the browser suites, Windows, the launchers, the EXE builder, any owner-PC check.

## Headline

1. **The game logic core is intact.** No file in `packages/domain`, `packages/data`, `packages/ai` or `apps/batch` changed. The frozen scoring kernel, generator, engines and random stream are untouched. New randomness goes through addressed seeds. (Verified by `git diff --stat`.)
2. **Local unit gate passes.** `npm run verify:09:core` at `806ef50`: PASS, exit 0, 73 files, 773 tests, 335 s. Five stage test files take 98 to 184 s each.
3. **Hosted CI has been red on every commit since `161e781`.** Runs for `031abd3`, `3762ed3`, `d02e899`, `9e4ea36` and `8517205` all concluded `failure`; `806ef50` was still running at audit time. No document records this.
4. **Process rules were bypassed.** Twelve commits by "Lord Cricket Engineer" were pushed straight to `main` with no PR, no review and no green CI. Each claims "owner acceptance" without quoting the owner, while several stage reports still say "awaiting owner review".
5. **Scope went well past the brief.** Contracts, finances, youth, retirement, multi-year progression, spoken commentary and 2D highlights were all listed as Deferred in the design brief (§1, §16, Appendix E). The owner's 11 Nov direction approved three sequential milestones; Stages 5 to 10 have no authority in the repository. The "Master Build Brief" the stage docs cite does not exist in the repository.

So: a large amount of plausible, largely well-structured code exists, but it is unreviewed, CI-red, and in several places breaks the project's own versioning and safety rules.

## Findings

### High

| # | Finding | Status |
|---|---|---|
| H1 | **Shutdown endpoint is unprotected.** `start.mjs:91-101` only checks `remoteAddress`, which is always loopback because the server binds to 127.0.0.1. `serve-portable.mjs` and `LordCricketLauncher.cs` have no check. `tests/unit/windows-launcher.test.ts:89-92` asserts a bare POST returns 200. Any web page the player visits could stop the game server with a no-cors POST. No Host header check, so DNS rebinding is possible. | Verified (code); exploit [Inference] |

Same pattern in `squad-economy.ts` and a reduced session digest in `roster-t20-match.ts:16-33`. A tampered import carrying a known hash would pass. | Verified (code); exploit [Inference] |

### Medium

- Whole-store `projections.getAll()` reads on every commit and load (`persistence/src/persistent-world.ts:1164-1178, 1379, 1663, 1720`); every commit rewrites the full world history. Cost grows with career length. [Inference]
- Awards ledger is stored outside the transactional, leased commit, is never recomputed on import, and uses the current lifecycle for past seasons, so awards can drift from match facts. Opening Statistics writes a row into an old V0.1 save.
- Stage 3 and Stage 4 upgrades do not rekey pending managed-match bindings, so a match can be in flight in two slots.
- AI clubs cannot set training, so they accrue only rest days; the 12- and 20-season horizon tests use invented workloads rather than live play. Competitive imbalance [Inference].
- About 60 `localeCompare` calls feed hashed arrays and tie-breaks; ordering can differ by locale. Determinism across machines [Inference].
- Players can vanish without a record (unaffordable promoted youth; free agents aged 35+). Dead cap is reset without a ledger entry.
- Career simulation, statistics rebuilds and full commentary arrays run on or are copied to the UI thread; long red-ball matches and long careers will slow down [Inference].
- Sound is on by default (`packages/projections/src/audio-cues.ts:17`, `muted: false`). Verified.
- The EXE fallback registers `http://127.0.0.1:port/` with HttpListener, which normally needs admin rights or a URL reservation; nothing in CI compiles or runs the C# or PowerShell. The `.bat` → PowerShell bypass → runtime `csc.exe` compile chain is likely to attract antivirus or SmartScreen flags [Inference].
- No real IndexedDB tests for the persistent-world repository (aborts, lease contention, copy-source race).

### Low and maintainability

- Determinism tests compare two runs in one process; no pinned expected multi-season hash.

### Found while fixing Phase 1 (16 Nov, later)

- All four Windows UI failures also fail on Linux, every run, so they are not Windows timing: V01-018 expects the version-1 archive (spec out of date); edited-world recovery hit `SAVE_WORLD_TYPE_CONFLICT` because a lifecycle career match saved both its roster pack and its world copy (real bug: such matches could never be saved); the 150% layout overflowed by 32 px (real regression); the Stage 3 spec matched "Retired alumni record" twice (ambiguous test).
- The Stage 10 award provenance tag holds an unbroken version identifier and overflows a 390 px screen in Chromium on Linux (real defect, both full Chrome and the headless shell). Hosted Windows passed it, probably because of narrower fonts [Inference].
- Because the Linux job stops at the first failing step, the later steps (IndexedDB persistence specs, layout regressions in both browsers) have not run on hosted Linux since `161e781`.
- `tests/m4/persistence.spec.ts` "manual copy, export and staged import" raced the import (failed 1 run in 3 locally, on unchanged `main` too).

## What is solid

- Frozen engines untouched; all new randomness seeded and addressed; no `Math.random` or `Date.now` in simulation or projections.
- One-transaction world commits with lease, revision compare-and-set and idempotent command ids; downgrade refused; copies to new slots never mutate the source; three-generation checkpoint recovery.
- All 334 JSON Schemas generated and drift-checked (`schemas:check` PASS).
- Presentation layers (commentary, field, audio cues, awards) are projected from canonical events, not invented by React. Reduced motion, keyboard alternatives and captions are present.

## Plan to finish

Ordered so that each phase leaves `main` green and reviewable. Each phase is a branch, a draft PR, green hosted CI, then owner merge.

### Phase 0: owner decisions (blocking)

1. **Scope.** Keep Stages 2 to 10 as delivered scope, or treat Stages 5 to 10 as experimental behind a feature flag until reviewed? The design brief deferred most of this work.
2. **Authority.** Commit the "Master Build Brief" to the repository, or retire it. One roadmap must govern.
3. **Concurrent agents.** Which agents may write to this repository, and on which branches? Pause the others while the stabilisation phases run, or conflicts will repeat.
4. **Branch protection.** Apply it (owner action; see docs/BRANCH_PROTECTION.md). Agents cannot and should not do this.
5. **Acceptance records.** Confirm or withdraw the Stage 2 to 10 "owner accepted" entries. Until confirmed, docs should say "implemented, local evidence only".

### Phase 1: make main green (about 1 to 2 days of agent work [Inference])

- Raise the Linux unit gate timeout to fit measured time with headroom, and split the slow stage tests into their own shard.
- Shard the Windows `match-ui` suite or raise its limit; record measured time.
- Fix V01-018 for the lifecycle archive version; fix the 150% layout; diagnose edited-world recovery and the Stage 3 spec on Windows.
- Exit criterion: hosted Linux and Windows green on `main`, with run links recorded.

### Phase 2: safety and format integrity

- Shutdown endpoint: per-launch random token plus Host and Origin allowlist on all three servers; negative test that a bare POST gets 403.
- Remove hash-trust shortcuts: cache only after every check passes; restore the full session tamper check; add tests that tampered objects carrying a known hash are rejected.
- New archive version identifiers for anything that can carry `awards-ledger.json`; old versions written byte-for-byte as before.
- Defensive filter for unknown `recordType` values, plus a documented "no rollback below this build" note.
- Rekey bindings on Stage 3 and Stage 4 upgrades.

### Phase 3: correctness of the career systems

- Awards computed inside the season commit using the lifecycle as it was that season; imports recomputed and compared.
- AI clubs get training through the same commands as the player; horizon tests use live play; pinned multi-season hashes on Linux and Windows.
- Code-point sorting for authoritative state (new state version); fix vanishing-player paths; record dead cap in the ledger.

### Phase 4: scale and performance

- Key-range reads on `[saveId, scope]` instead of `getAll()`; store completed seasons once and reference them.
- Event-archive retention or pruning policy, plus a 20 to 50 season soak measuring snapshot size and commit time against the performance budgets.
- Move career simulation and statistics into a worker; virtualise the commentary list.

### Phase 5: maintainability

- Move rollover into `packages/simulation`; one stats aggregator; split `service.ts` and `CareerApp.tsx` by domain and tab; one static server source.
- Real IndexedDB tests for the persistent-world repository.

### Phase 6: Windows delivery and release

- CI job that builds and runs the EXE as a non-admin user and checks health, path traversal and shutdown; fix the HttpListener prefix; decide on code signing; sound muted by default.
- Reconcile docs (fix hashes, counts, stale statements), regenerate RELEASE_RECORD.json, and record the owner's human gates as observed, not declared.
